# Q-BU standalone editor

`/` を開くと、クラス選択・ログイン・参加QRを経由せず編集画面が直接表示されます。
作品はサーバーへ送信せず、右上の「書き出し」から `.qbu`、色別STL、全色を統合したSTL、manifestをまとめたZIPとして端末へダウンロードします。

## ローカル起動

```bash
npm ci
npm run dev
```

`http://localhost:3000/` を開いて確認します。Production build の確認は次のとおりです。

```bash
npm run build
npm run start
```

## 書き出し・インポート仕様

- 作品名と1ブロックあたりの長さ（mm）を指定し、`<作品名>_YYYY-MM-DD.zip` を生成
- ZIP内は `<作品名>/0001/0001.qbu`、`0001_<作品名>_<色>.stl`、`0001_<作品名>_all.stl`、`<作品名>/manifest.csv`
- 「1つのSTLで出力」を選ぶと、全ブロックを単色として統合した `0001_<作品名>_all.stl` だけを直接ダウンロード
- クラス・参加コードを持たない公開版では、WS Dashboard互換のフォルダ番号として `0001` を使用
- 「色の切り替え」と「ユーザー設定」の間の「インポート」から `.qbu` または `.stl` を選択可能
- `.qbu` と `.stl` は画面へのドラッグ＆ドロップでも読み込み可能
- `.qbu` のインポート時は形式、座標、色、重複、グリッド範囲、最大999,999ブロック、100MB上限を検証
- `.stl` はASCII／バイナリ（64MBまで）に対応し、表面をボクセル化して縦横比を保ったまま最長辺を40ブロック以内に収める
- `.stl` の変換結果は選択した1色の半透明プレビューとして表示し、XYZ方向へ移動してから編集モデルへ配置
- `fetch`、Supabase、作品送信APIは使用しない
- Class ID、Project ID、確認コード、参加者トークン、個人情報は保存しない
- 編集中モデルとツールバー設定は、同じブラウザの `localStorage` に自動保存（20,000ブロックを超える作品は容量保護のため作品データの自動保存対象外）

`.qbu` のトップレベル形式は次のとおりです。

```json
{
  "format": "qbu-standalone",
  "version": 1,
  "app": "Q-BU",
  "exportedAt": "2026-01-01T00:00:00.000Z",
  "project": {
    "fileName": "Q-BU"
  },
  "editor": {
    "gridSize": 160,
    "maxBlocks": 999999,
    "blockSizeMm": 5
  },
  "model": {
    "version": 1,
    "blocks": [
      { "x": 0, "y": 0, "z": 0, "color": "white" }
    ]
  }
}
```

## 公開面

公開面は `/` のスタンドアロン編集画面だけです。旧版のソースは復元用に残していますが、
旧ページと `/api/**` は `middleware.ts` で404にしています。
